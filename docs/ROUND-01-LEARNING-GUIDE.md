# 1회차 학습 설명서

기간: 2026-09-10 ~ 2026-09-11

이 문서는 첫 구현에서 무엇을 만들었고 왜 그렇게 설계했는지 다시 설명하기 위한 개인 학습 자료다. 공개 저장소에 포함되어도 괜찮은 기술 내용만 기록한다.

## 이번에 만든 것

작은 궁정 세계의 캐릭터 상태와 두 행동을 Python으로 구현했다. 현재 장소, 활동, 보고서 검토, 의복 정리, 서류 정리 여부를 상태로 저장한다. 서류 정리와 접견실 이동은 프로그램이 조건을 검사한 뒤에만 실행한다.

아직 LLM, 장기 기억, 데이터베이스, 웹 API는 연결하지 않았다. 첫 회차의 목적은 라이브러리 없이 상태 기반 실행 흐름을 이해하고 검증하는 것이었다.

## 핵심 실행 흐름

```text
행동 제안
  → 허용된 행동인지 검증
  → 현재 상태로 실행 가능한지 검사
  → 행동 또는 도구 실행
  → 성공한 경우에만 상태 변경
  → 검증된 결과를 캐릭터 대사로 변환
```

LLM을 연결한 뒤에도 LLM이 상태를 직접 수정하지 않는다. 모델은 구조화된 행동을 제안하고, Python 코드가 허용 여부와 선행 조건을 검사한다.

## 코드에서 이해해야 할 부분

### 제안과 실행의 분리

`validate_action_proposal()`은 행동 이름만 검사하고 상태를 변경하지 않는다. `execute_action()`은 검증을 통과한 제안을 실제 행동 함수에 한 번만 전달한다.

이 구분이 없으면 모델이 지원하지 않는 행동을 말했을 때 프로그램이 그대로 실행하거나, 같은 행동 함수를 대사 생성 과정에서 다시 호출할 수 있다.

### 성공 이후의 상태 변경

`organize_documents()`는 장소, 현재 활동, 중복 여부, 도구 성공 여부를 확인한다. 도구가 실패하면 `documents_organized`를 변경하지 않는다.

```text
시도함 ≠ 성공함 ≠ 상태가 변경됨
```

상태 변경은 성공 결과가 확인된 뒤에만 일어난다.

### 중복 실행 방지

서류가 이미 정리되었다면 `already_completed`를 반환한다. 접견실 이동 후에는 현재 장소가 이미 접견실이므로 같은 이동 요청이 `move_not_allowed`로 거절된다.

중복 여부는 행동의 의미에 따라 다른 상태로 판단해야 한다. 나중에 “하루 한 번만 가능한 접견”이 필요하다면 장소 외에 접견 완료 상태가 별도로 필요하다.

### 실행 결과와 대사의 일치

`describe_action_result()`는 검증된 실행 결과를 대사로 바꾼다. 도구가 실패했다면 성공 대사를 만들지 않는다. 이는 모델이 실제로 일어나지 않은 행동을 완료했다고 말하는 오류를 줄이기 위한 경계다.

### 독립적인 테스트 상태

각 테스트는 `create_initial_state()`를 호출해 새로운 딕셔너리를 만든다. 한 테스트에서 변경한 장소나 준비 상태가 다음 테스트에 남지 않는다.

거절된 행동의 상태 불변은 다음 방식으로 검사한다.

```python
state_before_execution = state.copy()
result = execute_action({"action": "leave_palace"}, state)

assert result["reason"] == "unknown_action"
assert state == state_before_execution
```

현재 상태는 문자열과 불리언만 포함하므로 얕은 복사로 충분하다. 내부에 기억 목록이나 중첩 딕셔너리를 추가하면 깊은 복사 또는 상태 불변 구조를 검토해야 한다.

## 첫 회차에서 확인한 실패 사례

- 문자열 키 자체와 `state["key"]`에 저장된 값을 혼동할 수 있다.
- `is`는 일반적인 값 비교를 위한 연산자가 아니며 문자열 비교에는 `==`를 사용한다.
- 상태를 변경하는 함수를 두 번 호출하면 첫 호출의 결과가 두 번째 호출 조건에 영향을 준다.
- 전역 상태를 여러 테스트가 공유하면 이전 테스트 결과가 다음 테스트에 남는다.
- 반환 결과만 검사하면 상태가 실제로 변경되었는지 놓칠 수 있다.
- 행동을 테스트하기 전에 하위 행동 함수를 직접 실행하면 테스트 시작 조건이 달라진다.
- Python의 `None`과 문자열 `"None"`은 다르다.

## 테스트가 증명하는 범위

현재 테스트는 다음을 확인한다.

- 서류 정리 성공과 상태 변경.
- 도구 실패 시 상태 유지.
- 이미 완료된 행동의 중복 방지.
- 잘못된 장소와 작업 중 상태에서 실행 거절.
- 행동 누락과 미지원 행동 차단.
- 행동 없는 일반 대화와 형식 오류의 구분.
- 이동 선행 조건과 중복 이동 차단.
- 실행 결과에 맞는 대사 선택.
- 서류 정리 후 이동하는 두 턴의 상태 연결.

이는 작은 결정론적 엔진에 대한 검증이다. LLM 응답 품질이나 기억 검색 성능을 검증한 결과는 아니다.

## 면접에서 설명할 수 있어야 할 내용

1. LLM이 행동을 직접 실행하거나 상태를 수정하게 하지 않은 이유.
2. 행동 제안 검증과 행동 선행 조건 검사가 어떻게 다른지.
3. 도구 실패 후 상태를 유지해야 하는 이유.
4. 중복 실행을 어떤 상태로 감지하는지.
5. 테스트마다 새 상태를 만드는 이유.
6. 실행 결과를 변수에 저장해 한 번만 사용하는 이유.
7. 현재 구현이 보장하는 것과 아직 구현하지 않은 것.
